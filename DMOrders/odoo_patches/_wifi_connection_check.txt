9) SI ALGO FALLA — SIGUIENTE PASO EXACTO
================================================================================
A) La tablet no abre http://192.168.205.99:8069
   - Confirmar que tablet y PC están en la misma WiFi.
   - Desde el PC, repetir: curl http://192.168.205.99:8069/web/login
   - Si el PC responde 200 pero la tablet no: revisar aislamiento de
     clientes (AP isolation / guest WiFi) en el router/AP.
   - Verificar regla firewall "Odoo 8069 LAN" sigue habilitada:
       netsh advfirewall firewall show rule name="Odoo 8069 LAN"

B) Desde Windows tampoco responde 8069
   - Ver si Odoo corre en WSL:
       wsl -d Ubuntu-24.04 -u rchonillo -- pgrep -af odoo-bin
   - Si no corre: arrancar Odoo con odoo_linux.conf (como en VS Code debug).
   - Ver portproxy y que connectaddress = IP actual de WSL:
       wsl -d Ubuntu-24.04 -- hostname -I
       netsh interface portproxy show all
   - Si la IP WSL cambió, actualizar portproxy (comando en sección 2).

C) No usar la IP de WSL (172.18.x.x) en la tablet
   - Esa red es Hyper-V/WSL; la tablet no la alcanza de forma fiable.
   - Siempre usar la IP WiFi de Windows: 192.168.205.99

D) appsettings / conexiones de la app siguen con IPs viejas
   - Actualizar BaseUrl / Host a http://192.168.205.99:8069
   - Tras otro cambio de WiFi, volver a chequear ipconfig y actualizar.

E) Login / dbfilter
   - dbfilter = qa.macronegocios
   - Si el login pide BD o falla el filtro, usar el nombre de BD esperado
     por ese filtro o ajustar dbfilter en odoo_linux.conf.
